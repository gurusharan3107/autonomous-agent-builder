Agent Harness Audit: autonomous-agent-builder

Audited 2026-05-23 · agentharness-audit v1.0
5.7/10 Overall Quality Score
autonomous-agent-builder is a production-grade SDLC orchestration harness built on the Claude Agent SDK. Its strongest aspects are subagent delegation (6 typed specialist agents returning structured JSON evidence, each bounded to their phase) and per-turn truth-grounding (structural hooks enforce workspace isolation, bash argv safety, and CLAUDE.md block ownership). The harness's biggest gaps are skill lifecycle (subagent definitions are static code — no curator, no stale/archive state machine), mechanical learning loop (no turn-counter nudges for autonomous memory writes), and model-adaptive guidance (no per-family prompt injection; generic guidance applies equally to all runtimes). Closing these three gaps would lift the overall score to approximately 7.5.

Principle Deep-Dives

7.5/10 P01 — Cache-Stable System Prompt
Found: runner_options.py:80–87 uses system_prompt: {type: "preset", preset: "claude_code", exclude_dynamic_sections: True} — delegates system prompt assembly to the Claude Code SDK preset, which handles cache stability. _AUTOCOMPACT_STRATEGIES (execution_policy.py:56–66) controls which phases re-enable compaction. Agent prompt templates in definitions.py are static Python strings with template vars — stable within a phase run.
Missing: No three-tier design (stable/context/volatile sections). No explicit date-only timestamp discipline documented in code. No _cached_system_prompt field or invalidation trigger documented; cache behavior is entirely delegated to the SDK without a builder-owned invariant. Prompt template vars (e.g., {workspace_path}, {user_message}) change per call, but these are injected into the user message, not the system prompt — so this is fine.
To reach 9.5: Add a code comment in runner_options.py:build_options_kwargs documenting the cache invariant: "system_prompt preset is byte-stable; per-run vars injected as user message only." Ensure no volatile data (timestamps, session IDs) is ever placed in the system prompt object. Add a test asserting the system_prompt dict is identical across two consecutive build_options_kwargs calls for the same agent.
6.5/10 P02 — Deferred Context Loading
Found: Knowledge base uses search-then-fetch: mcp__builder__kb_search returns candidates, mcp__builder__kb_show fetches full content on demand (tool_registry.py:302–331). Memory similarly uses mcp__builder__memory_search + on-demand access. get_tool_prompt_context() (tool_registry.py:133–152) explicitly avoids re-emitting full tool schemas: "The SDK already registers full tool schemas… repeating that listing wastes tokens."
Missing: No ToolSearch-style deferred schema loading — all allowed tools for an agent are passed upfront as a static list to the SDK (runner_options.py:79). No MEMORY.md lightweight index pattern for the builder's own agent context. Skills (subagent definitions) are loaded as code constants, not description-only deferred objects. No lazy routing layer.
To reach 9.5: In agents/tool_registry.py, add a ToolSearch tool that returns full schema for a named tool on demand. Reduce the default allowed_tools list to only universally-needed tools; let agents call ToolSearch before invoking unfamiliar MCP tools. Add a .builder/TOOL_INDEX.md lightweight index listing tool names + one-line descriptions.
3.5/10 P03 — Mechanical Learning Loop (Write Path)
Found: The optimization-agent (definitions.py:759–892) reviews observability telemetry post-sprint and can update CLAUDE.md guidance — a learning mechanism, but triggered by sprint lifecycle, not by turn counter. Agents can write memory via mcp__builder__memory_add when their prompt instructs it. AGENTS.md documents: "After a user correction… add repo memory."
Missing: No turn-counter nudge. No iteration-counter skill nudge. No autonomous memory write that fires without operator instruction. No background curator. No counter that survives process restart by hydrating from history. The optimization-agent is dispatched by the orchestrator post-ship, not by a turn limit.
To reach 9.5: In orchestrator/orchestrator.py, add a _turns_since_memory_nudge counter. After every N turns (configurable, default 5), emit a system nudge instructing the active agent to call mcp__builder__memory_add for any non-obvious decision made this session. Persist the counter in agent_runs so it survives restart. Add a forked review pass to optimization-agent that runs autonomously after every sprint without requiring a human trigger.
6.5/10 P04 — Strong Read Path (Retrieval)
Found: mcp__builder__kb_search + mcp__builder__kb_show (tool_registry.py:302–331) implement index-then-fetch for the knowledge base. mcp__builder__memory_search provides keyword search over memory (tool_registry.py:452–459). AGENTS.md contains explicit retrieval doctrine: "Retrieve before recall for unfamiliar/risky work." workflow --docs-dir docs summary/read/search commands provide doc retrieval. .memory/INDEX.md exists as a lightweight memory index.
Missing: No FTS5 session search for agents — cross-session recall requires the builder logs CLI, which is not agent-accessible as a tool. No dedicated session_search tool returning LLM-readable summaries. No Honcho-style user modeling. Memory index exists for the operator but not injected as a lightweight list into agent context.
To reach 9.5: Add a mcp__builder__session_search MCP tool that runs FTS over agent_run_events and returns bounded summaries. Register it in tool_registry.py under READ_ONLY_SPECIALIST_TOOLS. Add an explicit retrieval rule to the chat agent prompt: "For cross-session context, use mcp__builder__session_search before answering from memory."
4.0/10 P05 — Model-Adaptive Guidance
Found: execution_policy.py:217–226 (_thinking_for_model) detects model family to configure thinking: Haiku and GPT get None (no thinking), Sonnet/Opus get {"type": "adaptive"}. Effort levels are set per agent role in _AGENT_POLICY. The runtime factory (runtime/factory.py) maps SDKs to default models.
Missing: No per-family prompt guidance injection. GPT/Codex models in the codex_sdk lane receive the same system prompt content as Claude — no tool-use enforcement guidance added. No Google Gemini handling. No configurable override for per-model behavioral blocks. The thinking adaptation is invisible to the model itself.
To reach 9.5: In agents/runner_options.py::build_options_kwargs, detect the model substring and append family-specific guidance to the system prompt's stable tier. Define OPENAI_MODEL_EXECUTION_GUIDANCE (tool-use enforcement for GPT/Codex/grok) and GOOGLE_MODEL_OPERATIONAL_GUIDANCE (conciseness, parallel calls for Gemini/Gemma) as constants in agents/model_guidance.py. Reference pattern: Hermes agent/system_prompt.py:160–168.
8.0/10 P06 — Subagent Delegation as Context Isolation
Found: subagent_definitions.py:23–216 defines 6 typed specialist subagents: repo-researcher, browser-verifier, build-verifier, security-reviewer, pr-reviewer, documentation-agent. Each is bounded to read-only or verification tools. Every subagent prompt ends with "Always finish with exactly one JSON object" — structured evidence, not full traces. Subagents use Haiku for cheap specialist lanes (execution_policy.py:229–241). Subagent assignments are encoded per-phase in _AGENT_POLICY.
Missing: No explicit parallel subagent orchestration. Subagent JSON contract is instructed in prompts, not enforced structurally by a harness-level validator. The SubagentStop hook (hooks.py:517–536) audits completion but does not validate JSON shape.
To reach 9.5: Add JSON schema validation in hooks.py::audit_subagent_stop — parse the subagent output and block if the required JSON fields are absent. Add a parallel subagent dispatch path for phases that assign multiple subagents (e.g., build-verifier and browser-verifier running concurrently). Document the evidence contract in docs/subagent-contracts.md.
2.0/10 P07 — Skill Lifecycle / Self-Pruning
Found: Subagent definitions exist as versioned Python constants in agents/subagent_definitions.py. The optimization-agent can update CLAUDE.md guidance blocks (definitions.py:759–892). Operator-facing skills in .claude/skills/ are managed manually via skills-lock.json.
Missing: No curator process. No stale/archive/reactivate state machine for subagent definitions or operator skills. No autonomous LLM review pass. No pre-mutation snapshot. No REPORT.md diff after skill mutations. Subagents are never automatically deprecated based on usage data.
To reach 9.5: Create agents/curator.py. Add a state field (active|stale|archived), last_used_at, and use_count to SubagentDefinition. Implement apply_automatic_transitions() (stale after 30 days unused, archived after 90). Add run_curator_review() that spawns a forked agent to review stale subagents. Take a pre-snapshot with snapshot_subagents() before any mutation. Schedule curator runs after each sprint via the existing post-ship hook in orchestrator/post_ship_optimization.py. Reference: Hermes agent/curator.py:1369–1450.
7.5/10 P08 — Per-Turn Truth-Grounding
Found: hooks.py:70–211 structurally enforces workspace boundary (file ops blocked outside workspace), bash argv safety (no shell metacharacters), KB/memory write bypass blocked (agents must use MCP tools), and CLAUDE.md per-block ownership (hooks.py:228–402). AGENTS.md contains "Retrieve before recall for unfamiliar/risky work" and "Correct wrong assumptions immediately." Global CLAUDE.md has "Before recommending from memory: check the file exists; grep for the function." Quality gate commands (builder quality-gate <surface>) are listed in AGENTS.md.
Missing: No automated stale-memory detection at harness level (only operator instruction). No harness-level block for memory-based recommendations that haven't been file-verified. The retrieve-before-recall doctrine is in operator instructions but not checked by a hook on every tool call that reads memory.
To reach 9.5: Add a written_at field to all memory entries. In agents/hooks.py, add a PostToolUse hook for mcp__builder__memory_search that warns when the returned entry's written_at predates the workspace's last git commit — signaling potentially stale memory. Add this warning to the tool response so the agent sees it automatically.
5.5/10 P09 — Operator Ergonomics
Found: Dashboard-first design with a React frontend at port 8000. Auth via CLAUDE_CODE_OAUTH_TOKEN — no API key juggling for Claude provider. The init-project-chat agent (definitions.py:194–243) runs a structured requirements interview using AskUserQuestion. builder doctor command exists. Docker Compose for containerized deployment (docker/docker-compose.yml). Onboarding has 7 explicit phases (onboarding.py:71–80).
Missing: No one-line curl install script. Setup requires Python 3.11+, uv/pip, database initialization, and multiple CLI steps — not achievable by a smart non-expert in under 5 minutes without prior context. No builder setup wizard covering all configuration. No guided first-run that probes Claude availability before asking for project details.
To reach 9.5: Create scripts/install.sh — one-liner that installs the package, sets PATH, and prints "Run: builder init". Add a builder setup command in cli/commands/init.py that guides through: provider choice, OAuth vs API key, workspace directory, optional Docker. The guided onboarding wizard already exists via init-project-chat — link it from the setup command as the final step.
6.5/10 P10 — Security / Trust Model
Found: hooks.py:70–211 blocks writes outside workspace, ~/.codex access, KB direct writes, and memory direct writes. hooks.py:406–457 blocks shell metacharacters in Bash tool. hooks.py:228–402 enforces CLAUDE.md per-block ownership. runner_options.py:86: strict_mcp_config: True. runner_options.py:101: disable-slash-commands. Full tool-use audit trail via audit_log_tool_use persisted to DB. OneCLI boundary for auth.
Missing: No OS-level sandbox (Seatbelt on macOS, seccomp on Linux). permission_mode: "dontAsk" in background phases means all tools auto-approved — no per-tool allowlist enforced at OS level. No network isolation (agents can make arbitrary network calls via Bash). Audit log is DB-backed but not tamper-evident (signed). No capability-based restriction for the shell tool.
To reach 9.5: Add a AGENT_NETWORK_DISABLED env variable check in hooks.py::validate_bash_argv — block curl, wget, fetch, nc commands when set. On Linux, wrap the subprocess in a seccomp profile via unshare or bubblewrap in agents/runner.py::_execute_query. Expose a per-phase tool allowlist in execution_policy.py::AgentRuntimePolicy and enforce it in the PreToolUse hook.

6.0/10 P12 — Compaction Under Pressure
Found: execution_policy.py:56–66 defines _AUTOCOMPACT_STRATEGIES for long-running phases (planner 20t, code-gen 30t, etc.); runner_options.py:86–87 sets {"autoCompactEnabled": true} for these phases — delegates pre-turn compaction to the Claude SDK. hooks_trim.py:1–101 implements a PostToolUse output-trim hook: Bash, Read, run_tests, run_linter outputs truncated at 8,000 chars before the model re-reads them. Model fallback on empty result (runner.py:443–476).
Missing: No mid-turn (streaming) compaction. No multiple compaction strategies (only autoCompact delegation). No harness-level loop detection after compression. No analytics/telemetry on compaction events (events not tagged as compaction_fired). No configurable TruncationPolicy per tool type.
To reach 9.5: In agents/runner.py::_execute_query, detect ContextLengthExceeded from SDK and retry with manual compaction (summarize the middle turns). Add a compaction_event structlog entry that captures strategy, trigger, tokens before/after. Add loop detection: if compaction fired within the last 2 turns and context is still over threshold, raise CompactionLoopError. Reference: Codex compact.rs three-mode compaction.
