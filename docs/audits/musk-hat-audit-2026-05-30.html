The Cardinal Sin · Criterion 2

It only grows

A 0.08 deletion ratio means for every ~12 lines added in the last 90 days, ~1 was removed. Musk's rule is the inverse: if you're not adding back 10% of what you delete, you didn't delete enough.

80,845 src LOC across 268 files, with almost no pruning pressure. Six files exceed 1,000 lines — onboarding.py (1,931), evidence_graph.py (1,817), dashboard_api.py (1,736), kb.py (1,735). Each is a comprehension tax that compounds.

This is the single worst signal in the audit — and the one the hat weights above all others. Lines of code are a liability carried forever, not an asset banked once.

Why it scores so low

Growth-only isn't inherently bad for a young product. It becomes the cardinal sin here because the growth includes provably-deletable mass: a duplicate API surface and dead runtime lanes (next two sections). Discipline exists everywhere except the one place it matters most.

Verified Finding · Route-Level

Two FastAPI apps that have diverged

Two distinct apps with two launchers: embedded/server/app.py (13,609 LOC) booted by builder start — the operator-facing path and the richer surface — and api/app.py (130 LOC shell) booted only by main.py via a dev-server script. CLAUDE.md institutionalizes the tax: "Keep API retrieval routes in sync across the main app and embedded server." But the fix is not "delete api/" — much of that package is shared core the embedded server imports (see correction below). Keep embedded/server; delete only the redundant shell.

Exact-match comparison undercounts. api/ serves KB as /search, /tags, /{doc_id}; embedded/ serves the same KB as /kb/search, /kb/tags, /kb/{doc_id} — identical functionality, different prefix. Real duplication is higher than 30.

Verified Finding · Requirements Sanity

Three runtimes for lanes nobody can ship on

The factory string-dispatches 5 runtime adapters. But CLAUDE.md is explicit: "user-facing lanes are only claude and codex_sdk… compatibility adapters must not be used as sprint validation lanes." Three adapters — openai_runtime.py (282), opencode_runtime.py (21), codex_cli_runtime.py (635) — have zero references outside runtime/ and tests. That's 938 LOC of engineering invested in surfaces the product forbids shipping on: the smartest failure mode — optimizing a part that shouldn't exist.

Credit Where Due

What it does right

The hat rarely praises — these are genuine strengths, and the first one is exactly what makes aggressive deletion safe to attempt here.

  • Cycle time is genuinely excellent. 1.5s to collect 1,564 tests is rare at this size; iteration speed is preserved.
  • Near-zero rot. 1 TODO, 6 deprecated markers across 80k LOC. The code that exists is maintained.
  • Ownership is unusually well-articulated. The CLAUDE.md boundary doc is the "one owner per concern" discipline the hat wants — the gap is enforcement, not intent.

The punchline

This is a well-run shop building too many parts. One API surface, two runtimes not five, and a deletion habit to match the strong commit cadence. The disciplined iteration speed is the asset that makes the cuts low-risk.

Caveat: this is a synthesis of Musk's publicly-stated engineering algorithm (Starbase / Tesla) mapped onto software — a deliberately provocative lens, not a balanced rubric. Its blind spots (it under-weights correctness, security, long-horizon maintainability) are real, which is why it pairs well against a conventional review rather than replacing one.
