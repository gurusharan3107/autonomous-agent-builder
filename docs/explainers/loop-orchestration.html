Loop Orchestration Map

6 loops, all on-demand — no cron fires automatically. The master loop is the only entry point: the operator triggers it once and it decides at runtime which sub-loops to run, in what order, and which to parallelize. Maintenance is dispatched as a background subagent (propose-only → safe to parallelize); commit loops run sequentially. Master self-introspects mid-run and encodes learnings for future agents.

Phase 1 ASSESS 🔵 always first · parallel reads
Issue all four reads as concurrent tool calls in one message — no sequential waiting:
🔴 CI health — gh run list --branch master --limit 3 --json + read ci_health from watermarks 📋 Watermarks — read loop-runs-state.json: which sub-loops are stale (null or > 7 days)? 📑 Open work — grep -c '^\- \[ \]' ROADMAP.md + skim top 5 P1/P2 items 🔍 Recent friction — builder agent sessions --limit 10 --json: error patterns, hangs, repeated failures from last 24h
Synthesize all four signals before making any routing decision.
→ produces: CI status, stale-loop set, open-work depth, friction signal — input to Phase 2
Phase 2 PLAN 🗺️ state routing before executing
Decide which sub-loops to run this tick, in what order, and which to parallelize. State the plan in 3–5 lines before executing anything. Key decision rules:
🔴 CI RED → P0: run stabilization CI-fix path immediately; hold everything else 🟢 Maintenance stale → dispatch as background subagent (Agent tool, run_in_background=true) while main thread finishes assessment 🟡 Stabilization current (ran today) → skip even if ROADMAP has items 🔬 Codebase-review slice sha unchanged → skip; no-op tick
Parallelism rule: maintenance is always safe to parallelize (propose-only, never commits). Stabilization and codebase-review are sequential only — both commit, never run concurrently.
→ explicit routing plan: which loops, what order, what's parallel — stated before any execution
Phase 3 EXECUTE 🟡 adaptive · deviate when evidence demands
Run each selected sub-loop by reading its prompt from loops.json by id. After each committing sub-loop, re-assess CI health before starting the next. Maintenance proposals land in context before stabilization dispatches — use session-backed findings as higher-confidence targets when selecting what to fix.
Mid-run self-introspection — when master encounters unexpected friction (wrong hypothesis, CI surprise, missing context, misrouted fix, repeated revert): stop at that moment. Diagnose root cause. If non-obvious or would recur: immediately file a backlog item or propose a loop-prompt edit via AskUserQuestion — then continue. Do NOT defer to Phase 4; context is richest at the moment of friction.
🔍 maintenance — background subagent (propose-only) 🐛 stabilization — sequential, main thread, commit-on-green 🔬 codebase-review — sequential, main thread, one bounded slice
→ commits from stabilization/codebase-review; maintenance proposals collected; mid-run learnings encoded inline
Phase 4 RETROSPECT 🔵 always runs · even if no loops ran
Honest post-tick reflection — the most important phase for future agents:
🗂️ Decisions — what routing choices were made; were any wrong in hindsight? ⚡ Friction log — what slowed execution (missing state, ambiguous prompts, wrong CI read) 📊 Pattern analysis — mine tick sessions; ≥ 2 sessions same pattern → file improvement backlog item; novel → propose builder memory add ✨ Self-optimize fold-in — if hygiene watermark > 7 days: run /self-optimize (clustering lane) over dev sessions, propose surface edits, update hygiene watermark
→ updates loop watermarks for ran sub-loops only; sets master to today; updates ci_health

Hard Constraints

✍️Main thread is sole writer — subagents propose only; no subagent touches git
🔀Parallelism: propose-only only — maintenance dispatched as background subagent; commit loops (stabilization, codebase-review) are always sequential
🔴CI gate is P0 — if master CI is red, fix CI before any ROADMAP burn-down
🔬Diagnose locally first — never pin a dep on circumstantial evidence; run the failing tests before committing
🏗️Never edit managed-app workspaces — this source repo is the only write surface
