How hermes-chrome works

The extension bridge that gives agents a visible, cursor-driven handle on your running Chrome window — authenticated tabs, real DOM, no headless sandbox.

Extension bridge Unix socket Visible cursor hermes-chrome ONLY — no chrome-devtools / playwright

§1Session flow

Every browser session follows exactly these seven steps in order. Click any step to expand the detail.

1
Always first
Preflight
Run preflight.sh — must exit 0 before any bridge call.
bash .claude/plugin/hermes_chrome/scripts/preflight.sh

Preflight auto-fixes: file deployment drift → runs sync.sh; stale socket → removes + wakes Chrome via PowerShell; socket missing → wakes Chrome, waits 15 s.

If it fails: open Chrome, navigate to any HTTPS page, re-run. Never skip this step.
✓ Preflight OK
Active tab URL printed — proceed to step 2.
✗ Preflight FAIL
Chrome not open or socket down — open Chrome → HTTPS page → retry.
2
Decide once
Tab decision
Choose useSelectedTab before the first bridge call — never change it mid-session.
Active tab is on the target domain?
→ useSelectedTab: True for every call. Never open a new tab.

Active tab is blocked (file://, chrome://, about:*, extension page)?
→ useSelectedTab: False on the first call only, then True for all subsequent calls.

Repeated useSelectedTab: False = new tab + new group every call = orphaned tab pile. Always wrong.
3
Inline only
Define bridge()
Copy the socket snippet from references/operate.md into every Bash Python block.
There is no script file to call. bridge_call.py, bridge_client.js, and from native_host import bridge do not exist. The function is always defined inline: 
import socket, json, os

def bridge(payload, timeout=45):
    SOCK = os.environ.get("HERMES_CHROME_BRIDGE_SOCKET",
        os.path.expanduser("~/.hermes/run/chrome-bridge.sock"))
    s = socket.socket(socket.AF_UNIX, socket.SOCK_STREAM)
    s.settimeout(timeout)
    with s:
        s.connect(SOCK)
        s.sendall(json.dumps(payload).encode())
        chunks = []
        while True:
            chunk = s.recv(65536)
            if not chunk: break
            chunks.append(chunk)
    return json.loads(b"".join(chunks))
4
Always
Ground state
Call page_context first — 1 KB, confirms URL + title before acting.
bridge({"type":"run","useSelectedTab":True,"actions":[{"type":"page_context"}]})

Never open with snapshot (8–30× bigger). Record the starting URL — you'll restore it at closeout.
5
One call per task
Batch actions
All actions for a task go in a single bridge() call — one socket round-trip.
r = bridge({"type": "run", "sessionName": "my-task",
            "useSelectedTab": True, "actions": [
  {"type": "goto", "url": "http://localhost:9876"},
  {"type": "wait_for_selector", "selector": "h1", "timeout": 5000},
  {"type": "click_text", "text": "Submit"},
  {"type": "page_context"}
]})
Action escalation: page_context (1 KB) → text (2–4 KB) → snapshot (3–8 KB) → zoom (region only) → screenshot (full viewport, disk only). Use the smallest that answers the question.
6
After each action
Verify result
Re-run page_context to confirm expected URL + state. Zoom for visual proof.
Never chain an interactive action (click_text, fill_selector) directly after goto in the same batch — the DOM may not be ready. Land goto + wait_for_selector first, then act in the next call.

On failure: get a fresh snapshot before retrying — selectors go stale. One retry only; if still failing, enter Optimize (references/optimize.md).
✓
Mandatory — even on failure
Closeout
Screenshot + status check + close agent-opened tabs. Leave Chrome clean.
1. screenshot + page_context → visual proof + final URL
2. bridge({"type":"status","timeoutSeconds":5}) → must return success: true
3. close_tab on every tab the agent opened — never close the operator's original tab
4. Handoff line: "Chrome left at <url>, bridge ready, N tabs closed."

Skipping closeout leaves a stale socket or orphaned tabs for the next agent.
One sessionName = one tab. The bridge persists the session → tab mapping in service_worker.js sessionTabs. Pass the same sessionName for the whole task and you get exactly one reused tab, no orphan proliferation.

§2Action levels

Always start with the smallest action that answers the question. Escalate only when needed.

L1
page_context — ~1 KB · URL, headings, nav, buttons, inputs. Start here every turn.
L2
text — 2–4 KB · Full visible page text. Use to read content / tables.
L3
snapshot — 3–8 KB · Interactive elements with CSS selectors. Use only when you need a selector for click_selector or fill_selector.
L3b
zoom {x0,y0,x1,y1} — 2–10 KB inline JPEG. Visual proof of one region. A full-viewport zoom is screenshot-sized — always scope the region tightly.
L4
screenshot — full viewport JPEG to disk. Returns a path, not inline bytes. Use sparingly — one at closeout as final proof.
L5
evaluate — read-only JS. Last resort for reading hidden state. Never to click, submit, or mutate.

§3When to use

The bridge is the only tool for any task that requires real browser state — authenticated sessions, SPAs, live UI validation.

🔍
UI verification after a code change
Navigate to the changed surface, screenshot + page_context as evidence. The browser-verifier agent uses this lane.
🔐
Authenticated tasks
The bridge runs in your live Chrome profile — cookies, session tokens, and local storage are all real. No login needed.
📋
Form filling & submission
fill_selector → click_text → wait_for_url_change → page_context. Cursor animates on screen so you can see every step.
🧭
Dashboard / SPA navigation
goto + wait_for_selector avoids the networkidle-hang that kills Playwright on SPAs with SSE long-polls (B4 trap).
📸
Visual proof / screenshots
Use zoom for a specific panel (2–10 KB inline), screenshot for the full viewport (disk path). Always include one at closeout.
🖱️
Operator-visible agent work
Every click animates a cursor that the operator can watch in real time. Never hide the cursor — it's the only live signal the agent is acting.

§4Dead ends — never do these

✕
python3 .claude/plugin/hermes_chrome/scripts/bridge_call.py
This file does not exist. bridge() is always defined inline — copy the socket snippet from references/operate.md.
✕
python3 .claude/plugin/hermes_chrome/scripts/bridge_client.js
This file does not exist. There is no bridge_client.js in the plugin. Define bridge() inline using the socket snippet from references/operate.md.
✕
from native_host import bridge
native_host.py has no bridge() export. It is a native messaging host process, not an importable module.
✕
chrome-cli tabs / chrome-cli list / chrome-cli screenshot
chrome-cli only has doctor and launch. Any other subcommand is hallucinated and will fail immediately.

§5Troubleshooting

Bridge socket not reachable / diagnose BLOCKED FAIL
Signal: preflight.sh exits 1 with BLOCKED FAIL bridge_socket_reachable.

Cause: Chrome is not running, or the Hermes extension is not enabled.

Fix:
1. Open Chrome (Windows side)
2. Navigate to any https:// page
3. Re-run bash .claude/plugin/hermes_chrome/scripts/preflight.sh

preflight.sh auto-tries PowerShell Chrome wake + 15 s wait before giving up — so usually it recovers on its own.
Cursor visible but click lands on wrong element
Signal: click_text returns a point but the page behaves unexpectedly.

Cause: Page was still animating (modal opening, dropdown expanding) when the click fired.

Fix: Add wait_for_selector on a stable post-animation element before clicking. Don't chain a click directly after goto in the same batch — always land + wait first.
Extension edits not taking effect
Signal: You edited a file under .claude/plugin/hermes_chrome/extension/ but Chrome still shows the old behaviour.

Fix: Run bash .claude/plugin/hermes_chrome/scripts/sync.sh. It rsyncs repo → global plugin AND repo/extension → the Windows-side Chrome-loaded folder, then hot-reloads Chrome via the bridge socket. Toolbar icon may stay cached — manually reload on chrome://extensions to clear it.
Socket dropped mid-session (OSError)
Cause: Chrome MV3 service workers idle out after ~30 s. The keep-alive alarm fires every 25 s to prevent this, but system suspend or display-off can kill the worker between alarm ticks.

Fix (inline recovery): Use bridge_call() instead of bridge() — it wraps the call with one preflight.sh retry on OSError. Full snippet in references/operate.md § Mid-session socket drop recovery. One retry only; if still failing, open references/optimize.md.
Content script blocked — page_context returns blocked:true
Signal: preflight prints ⚠ Content script blocked on active tab.

Cause: Active tab is a chrome://, file://, about:*, or extension page — the extension cannot inject into these.

Fix: On the first bridge() call use useSelectedTab: False to open a fresh navigable tab, then switch to useSelectedTab: True for all subsequent calls.
screenshot_path not found after taking a screenshot
Cause: Screenshot action saves to ~/.hermes/cache/hermes-chrome/<id>.jpeg on the WSL side. The path in the result uses ~ expansion.

Fix: Open the file with explorer.exe "$(wslpath -w ~/.hermes/cache/hermes-chrome/<id>.jpeg)". Note: explorer.exe returns exit code 1 on WSL2 but the file opens correctly.
